Refined Numerics

Prologos supports refined numeric types — wrapper types that carry sign constraints at the type level. A PosInt is provably positive, a NegRat provably negative. These refine the standard numeric tower (Nat <: Int <: Rat) with finer subtyping:

Int Rat / | \ / \ NegInt Zero PosInt NegRat PosRat

Smart constructors validate at runtime and return Option; unsafe constructors trust the caller. The subtype declaration registers coercions so a PosInt can be used wherever Int is expected — the type checker inserts the unwrapping automatically.

This chapter also defines two abstract domains — Parity and Sign — which are data types used by the lattice framework for static analysis. They appear here because they are pure data types with no dependencies on the lattice machinery; their lattice instances and trait instances (Eq, Ord, GaloisConnection) live in the Lattices chapter under prologos::core::abstract-domains.

Part I — Refined Integers

prologos::data::refined-int
require [prologos::data::option :refer [Option some none]]

======================================== Refined Integer Types ======================================== Wrapper types for expressing numeric sign constraints at the type level. Smart constructors validate at runtime; unsafe constructors trust the caller.

Subtyping lattice (enforced by the type system via subtype declarations):

Int / | \ NegInt Zero PosInt

PosInt, NegInt, Zero are subtypes of Int — they can be used anywhere Int is expected.

Positive integers (value > 0)

data PosInt
  pos-int Int

Negative integers (value < 0)

data NegInt
  neg-int Int

Zero singleton

data Zero
  mk-zero

======================================== Smart Constructors (runtime-checked) ========================================

spec to-pos-int Int -> [Option PosInt]
defn to-pos-int [n]
  if [int-lt 0 n]
    [some [pos-int n]]
    none

spec to-neg-int Int -> [Option NegInt]
defn to-neg-int [n]
  if [int-lt n 0]
    [some [neg-int n]]
    none

spec is-zero? Int -> Bool
defn is-zero? [n]
  int-eq n 0

======================================== Unsafe Constructors (caller guarantees invariant) ========================================

spec unsafe-pos-int Int -> PosInt
defn unsafe-pos-int [n]
  pos-int n

spec unsafe-neg-int Int -> NegInt
defn unsafe-neg-int [n]
  neg-int n

======================================== Extractors ========================================

spec pos-int-val PosInt -> Int
defn pos-int-val [p]
  match p
    | pos-int n -> n

spec neg-int-val NegInt -> Int
defn neg-int-val [p]
  match p
    | neg-int n -> n

======================================== Conversion: back to Int ========================================

spec zero-to-int Zero -> Int
defn zero-to-int [z]
  match z
    | mk-zero -> 0

======================================== Subtype declarations ======================================== PosInt <: Int <: Rat (auto-inferred coercion: unwrap single-field constructor) NegInt <: Int <: Rat (auto-inferred coercion: unwrap single-field constructor) Zero <: Int <: Rat (explicit coercion via zero-to-int: nullary constructor)

subtype PosInt Int
subtype NegInt Int
subtype Zero Int via zero-to-int

Part III — Abstract Domains (Data Types)

prologos::data::parity

======================================== Parity Domain — Abstract parity analysis ======================================== Four-element lattice for parity abstraction:

parity-top / \ parity-even parity-odd \ / parity-bot

parity-bot = no information (unreachable) parity-even = definitely even parity-odd = definitely odd parity-top = unknown parity

data Parity
  parity-bot
  parity-even
  parity-odd
  parity-top
prologos::data::sign

======================================== Sign Domain — Abstract sign analysis ======================================== Eight-element powerset lattice ℘({neg, zero, pos}) — the Boolean cube Q₃. ⊑ = ⊆ ⊥ = sign-bot (∅) ⊤ = sign-top ({neg,zero,pos}) join = ∪

sign-bot = ∅ no information (unreachable) sign-neg = {neg} definitely negative sign-zero = {zero} definitely zero sign-pos = {pos} definitely positive sign-nonpos = {neg,zero} ≤ 0 sign-nonzero = {neg,pos} ≠ 0 sign-nonneg = {zero,pos} ≥ 0 sign-top = {neg,zero,pos} unknown sign

data Sign
  sign-bot
  sign-neg
  sign-zero
  sign-pos
  sign-nonpos
  sign-nonzero
  sign-nonneg
  sign-top
