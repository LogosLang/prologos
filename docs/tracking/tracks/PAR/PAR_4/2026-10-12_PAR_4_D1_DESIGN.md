## 1. Purpose and scope

Parallel execution of S0 (the monotone value stratum) as **scheduler technology**: the BSP scheduler
owns K persistent executors; each executor owns a partition of the cells and a memory region for
them; S0 fires write their own partition directly with no barrier inside S0; cross-partition
writes travel as owner-bucketed deltas; the only coordination is **quiescence detection at the
stratum boundary**, where it is unavoidable. Two halves, landable separately:

- **H-S (scheduler half)** — ownership, direct S0 writes, deltas, quiescence detection, the
  frozen bit, K as a cell, park/unpark. Applies to **every** cell. Removes the fire *protocol*
  cost (snapshot / returned network / output-set / diff / re-merge ≈ 2.3 of 2.8 KB per fire).
- **H-F (storage-tier half)** — a flat, region-allocated record representation for the lattices
  whose encoding is prefix-closed (one word, bitmask, tagged entries, small fixnum sets), behind
  the existing `specialized-cell-meta` seam. Removes the *write* cost for those cells.

Out of scope: interning/hash-consing of structured lattice values (Q3; later track); a new
partitioning algorithm beyond connected components + round-robin baseline; distributed execution.

## 4. The design on one page

**Two theorems carry it** (Stage 1 §0). (i) Asynchronous iteration (Üresin–Dubois 1990; Bertsekas
1983; Cousot RR-88): a monotone, inflationary operator on a product of per-cell lattices with
finite chains converges to the same least fixpoint under *any* schedule with causal reads, every
dirty cell eventually re-fired, and finite staleness — provided each component has one writer
whose view of it is never stale. (ii) CALM (Ameloot et al. 2013): monotone ⇔ coordination-free,
and fixpoint *detection* is non-monotone. Hence: no barrier inside S0; exactly one coordination
per stratum transition; ownership is the theorem's hypothesis, not an optimisation.

**The design sentence.** *The scheduler owns K executors; executor i owns partition Pᵢ (a cut of
the cell set computed at the topology stratum) and region Rᵢ (memory for Pᵢ's flat records); an
S0 fire runs on the executor that owns its home cell, writes home-partition cells directly, and
sends foreign writes as deltas to their owners' lanes; executors never wait on each other inside
S0; quiescence is detected by a counter scheme; the stratum boundary is the only barrier, where
the sequential non-monotone handlers (topology, S(−1), S1) run as today.*

**Layering** (`DESIGN_PRINCIPLES.org` § Orthogonality): the *cell* declares lattice, merge, and
storage (heap or a flat kind) — H-F lives here; the *propagator* declares reads/writes — unchanged;
the *scheduler* decides ownership, executor, and detection — H-S lives here. A K=1 executor under
DIRECT is Gauss–Seidel chaotic iteration; the current BSP scheduler remains a valid scheduler of
the same cells and propagators. No cell's semantics depend on which scheduler runs it (§10).

```
                 topology stratum (sequential, between S0 runs)
                 ─ partition cells → P₁…P_K ; (re)size regions R₁…R_K ; compaction
                                │ resume S0
  executor 1      executor 2     …     executor K           (persistent #:pool 'own threads)
  ┌──────────┐    ┌──────────┐         ┌──────────┐
  │ P₁, R₁   │    │ P₂, R₂   │         │ P_K, R_K │   own records: direct store + release
  │ worklist₁│    │ worklist₂│         │ worklist_K│   foreign write: push (cell, Δ) to lane[owner][me]
  │ lanes[1][*]   │ lanes[2][*]        │ lanes[K][*]  owner drains lanes: join Δ, mark dirty, enqueue
  │ prod₁ cons₁ idle₁ (padded)         …            │   counters for detection
  └──────────┘    └──────────┘         └──────────┘
                 detector: Σprod = Σcons ∧ ∀ idle, stable across two scans
                 ─ freeze S0 records → run stratum handlers → unfreeze → resume or finish
```

## 5. H-S — the scheduler half

### 5.1 Executors and K

- `scheduler-k-cell`: a max-merge cell on the scheduler's own network state, default
  `(max 1 (- physical-cores 2))`, owner-tunable; never oversubscribed (a descheduled spinner
  holds the detector for an OS quantum — MEASUREMENT, contention analysis §4). On SMT hosts the
  default follows physical cores. **K=1 is the sequential scheduler** — not a separate code path.
- Executors are persistent `#:pool 'own` threads created once per process (not per solve), parked
  on a per-executor box; one semaphore wake per *solve* (the 7.3 µs cost paid once), spin-wait
  with bounded backoff inside a solve (60 ns hops). Idle between queries = parked, 0 cores.
- All per-executor mutable state (`worklist`, lane heads, `prod`, `cons`, `idle`) lives in a
  **padded 16-slot fxvector per executor** (MEASUREMENT: consecutive boxes on one line cost 2×).

### 5.2 Ownership and partition

- `owner : cell-id → executor-index` is a function of the partition, computed at the **topology
  stratum** (the only time the cell set changes; Q5). Cells allocated mid-round by a fire (the
  PAR 1 namespaced path, `net-new-cell` with `current-cell-id-namespace ≠ 0`) are owned by the
  allocating executor until the next topology stratum rebalances.
- Partition policy is a **cost** choice, semantically free (CALM; Stage 1 T9). Baseline:
  round-robin by cell-id. Candidate: connected components of the declared cell–propagator graph
  (`MODULE_THEORY_LATTICES.md:257-264`), with *hub cells* (request accumulators,
  `worldview-cache-cell-id`, `fuel-cell-id`, `naf-pending-cell-id`) excluded from the cut
  because they are only read at the boundary (CONJECTURE A-8/Q4 — P0 measures the cut quality).
- A propagator's **home** is the owner of its first declared output cell (`propagator-outputs`,
  `propagator.rkt:364`). Its fire runs on its home executor; it reads any cell (acquire) and writes
  home cells directly; writes to foreign cells become deltas.

### 5.3 Writes, deltas, and lanes

- Home write: `join` on the owner's record, release-fenced store; if changed, mark dirty and
  enqueue dependents (the existing `prop-cell-dependents` filtered by component path and
  worldview, `filter-dependents-by-paths`) onto the owner's worklist — or, if a dependent's home
  is foreign, onto that owner's lane as a *fire request*.
- Foreign write: append `(cell-id, Δ)` to `lane[owner][me]` — a single-producer single-consumer
  append-only list, release on push, acquire on pop; no CAS. The owner drains its K−1 lanes at
  the top of each fire loop iteration and joins. Deltas are **δ-CRDT delta-groups** (Stage 1
  T13): no ordering, no acks, duplicates harmless *because merges are idempotent* (A-2).
- Reads of foreign cells are plain acquire loads of the owner's record. Under the asynchronous
  iteration theorem a stale read is permitted (finite staleness, A3): it costs an extra fire,
  never a wrong fixpoint. **This is the part Q1 audits** (§9 A-1): any S0 fire that reads a cell
  and acts on its *absence* or on *not-yet-written-this-round* is an undeclared stratum.

### 5.4 Quiescence detection replaces the round barrier

Per executor, padded: `prod` = deltas + fire requests sent, `cons` = received and processed,
`idle` = worklist empty ∧ lanes empty. The detector (the scheduler thread, or executor 0) scans
`Σprod = Σcons ∧ ∀i idleᵢ` twice with no change between scans (Mattern's double-count; the same
invariant as Dijkstra–Scholten with counters instead of a tree). PRECEDENT: Naiad frontiers,
LVish handler quiescence. Expected cost ≈ K × 60 ns ≈ the measured 0.8–1 µs barrier — paid once
per stratum transition, not per round (MEASUREMENT-to-be, P0 A-6).

### 5.5 The frozen bit

At detection, S0 records are **frozen** (one flag word per flat record; one bit in the heap
cell's meta). A frozen record rejects S0 writes by writing `'late-s0-write` to
`contradiction-cell-id` — a classified error, never a silent lost update (LVars `freeze`,
Stage 1 T11). Handlers write through their own API (they are non-monotone by declaration and run
sequentially at the boundary, as today). Unfreeze on resume. The bit turns a detection bug from
"nondeterministic answer" into "contradiction with provenance" — correctness as an architectural
property, not care.

### 5.6 The boundary, unchanged in meaning

The outer loop at `propagator.rkt:3309-3500` already is: *S0 to quiescence → topology-tier
handlers → value-tier handlers → repeat if any produced S0 work*. H-S replaces only the S0 inner
loop (`:3321-3400`: dedup, snapshot, `executor`, `bulk-merge-writes`, observer) with the executor
run + detector. `stratum-handlers` (`:3181-3224`), S(−1) retraction, S1 NAF, L1/L2 keep their
mechanism and their sequential order (their ordering is structural — `stratification.md` §Core).

### 5.7 Observers and statistics

`current-bsp-observer` and `current-bsp-round-stats` consume per-round diffs. Under DIRECT there
are no rounds. Provide the same information as *per-stratum-run* summaries (fires, writes, deltas,
detection latency) and keep the per-round form available only under the BSP scheduler. Flagged for
the owner (§14 O-3).

## 6. H-F — the storage-tier half

### 6.1 Flat record kinds

Admitted when the lattice's flat encoding is **prefix-closed**: every intermediate state a reader
can observe under the single-writer protocol is itself a lattice element (Stage 1 §2.6, A-4).

| storage kind | record | join | candidates (production) |
|---|---|---|---|
| `'flat-max` | one fixnum | `fxmax` | `counter-merge` (2), fuel/tropical cells, decision counters |
| `'flat-bitmask` | one fixnum | `fxior` | worldview bitmasks, cap-set-join when caps ≤ 60 |
| `'flat-tagged` | `[n, flag, (bm, v)×E]` | append (bm,v); v fixnum or **interned index** | `tagged-cell-value` (`decision-cell.rkt:397-500`); dedup entries on append (⚠ 2026-10-13: closed on the heap tier by DEFERRED 148 at the live site `:492`, `c62cd267`; pair-dedup bounds re-writes, **not ascending chains** — E sizing needs chain length or a bitmask-keyed join, which is sound only for ACI domain merges: [merge-laws note](2026-10-13_PAR_4_P0_DOMAIN_MERGE_LAWS_NOTE.md) §1, §5) |
| `'flat-fxset` | `[n, flag, x₁…x_E]` | append with owner-side dedup | small fixnum sets (`merge-set-union` where elements are ids) |

Everything else stays **heap tier**: an immutable persistent value published by a single pointer
store under release; the merge allocates as today, bounded by the intensity law (A-12). The
`specialized-cell-meta` struct (`propagator.rkt:329`) already carries `tier`/`storage`; today's
`storage` values are `'general` (8) and `'monotone-counter` (1): the seam is one enumeration
wider, not a new mechanism. The `net-cell-write` fast path (`:1899-1982`) dispatches on it today.

### 6.2 Regions

`Rᵢ` is a Tofte–Talpin region (Stage 1 T18): one `fxvector` per partition, bump-allocated, freed
in bulk. **Lifetimes are declared**, not inferred: `:network` (lives with the canonical network),
`:query` (freed at solve end), `:fork` (child of a `:query` region). No intra-region reclamation:
growth is bounded by **compaction at the topology stratum** (rewrite live records densely —
sequential, between S0 runs). Capacity is a cell written at the topology stratum (Q5). A record
that overflows E entries migrates to the heap tier at the next boundary (its slot stores an
escape pointer); the common case is sized by the P0 entries-per-cell distribution.

### 6.3 Fork and serialization

Two representations of a network: the **live** one (regions + heap slots, owned, during S0) and
the **value** one (today's persistent CHAMP `prop-network`, for `fork-prop-network`, `.pnet`,
tests). Fork at a boundary: copy the regions (MUSE copying; Stage 1 §2.7) if P0 Q2 finds forks are
≪ 1 per query, else partition-granular copy-on-write. `.pnet` serializes the value form; regions
are rebuilt at load (Q6). The value form is **materialized on demand** from the live form at a
boundary; it is never maintained during S0 (that maintenance *is* the 2.3 KB/fire ceremony).

### 6.4 What the fire protocol becomes

| today (`fire-and-collect-writes` `:2855`, `bulk-merge-writes` `:2966`) | H-S + H-F |
|---|---|
| snapshot network per round; fire returns `fire-result` with value-writes, new cells, new propagators | fire writes records directly; returns nothing; new cells/propagators go to the topology request cells (already the PAR 1 protocol) |
| `for/hasheq` output set; `champ-diff` per fire; `bulk-merge-writes` re-merges every write into the canonical CHAMP | no output set; no diff; join once at the owner |
| 2 819 B / ~1 500 ns per read+write fire (MEASUREMENT, census) | ~0 B for flat cells, merge bytes only for heap cells; 95–130 ns on the tagged lattice (MEASUREMENT, `arena-tagged3`) |

## 7. NTT speculative model

```prologos
;; ── lattices ────────────────────────────────────────────────────────────────
type ExecutorIdx := Nat                       ; 0 .. K-1

impl Lattice Nat :as max                      ; K, capacity, counters
  join | a b -> [max a b]
  bot -> 0

type Partition := Map CellId ExecutorIdx      ; written once per topology run
impl Lattice Partition
  join | p q -> [map-union-replace p q]       ; LWW per key — NOT a join in general;
                                              ; legal only because written at the
                                              ; topology stratum (non-monotone by declaration)

type Lane := List [CellId Delta]              ; append-only, SPSC
impl Lattice Lane
  join | a b -> [append-dedup a b]            ; idempotent because Delta joins are

type Frozen := unfrozen | frozen              ; two-point chain
impl Lattice Frozen
  join | unfrozen x -> x | x unfrozen -> x | frozen frozen -> frozen
  bot -> unfrozen

;; ── scheduler-state cells (on the scheduler's network, lifetime :persistent) ─
cell scheduler-k      : Cell Nat          ; owner-tunable; default cores-2
cell partition        : Cell Partition
cell region-capacity  : Cell (Vec K Nat)  ; per partition, max-merge
cell exec-prod        : Cell (Vec K Nat)  ; padded in the realization
cell exec-cons        : Cell (Vec K Nat)
cell exec-idle        : Cell (Vec K Bool) ; Bool as or-lattice RESET at resume → declared non-monotone
cell s0-frozen        : Cell Frozen       ; RESET at resume → declared non-monotone
cell lanes            : Cell (Vec K (Vec K Lane))

;; ── propagators ─────────────────────────────────────────────────────────────
propagator owner-drain [i : ExecutorIdx]
  :reads  [Cell (Vec K Lane)]              ; lanes[i][*]
  :writes [Cell L ...]                     ; the owned records (any L with Lattice L)
  [for-each-delta [cell d] [join-into cell d]]     ; all-at-once over the lane

propagator s0-fire [p : PropagatorId]
  :reads  [Cell L ...]                     ; p's declared inputs, any owner
  :writes [Cell L ...]                     ; p's declared outputs; foreign ones route to lanes
  [fire p]                                  ; monotone by default (A-1)

propagator quiescence-detector
  :reads  [Cell (Vec K Nat)] [Cell (Vec K Nat)] [Cell (Vec K Bool)]
  :writes [Cell Frozen]
  :non-monotone                             ; CALM: fixpoint detection is not monotone
  [when [and [= [sum prod] [sum cons]] [all idle] stable-twice] frozen]

propagator partitioner
  :reads  [Cell Topology]                  ; declared cell/propagator graph
  :writes [Cell Partition] [Cell (Vec K Nat)]
  :non-monotone                             ; replaces; runs at the topology stratum only
  [hypergraph-cut topology k]

;; ── stratification ──────────────────────────────────────────────────────────
stratification arena-scheduler
  :fiber S0        [s0-fire owner-drain]              ; monotone; K executors; no barrier
  :fiber boundary  [quiescence-detector]              ; non-monotone; produces `frozen`
  :fiber topology  [partitioner compaction]           ; non-monotone; sequential
  :fiber S(-1)     [process-retraction]               ; unchanged
  :fiber S1        [naf-handler]                      ; unchanged
  :order S0 -> boundary -> topology -> S(-1) -> S1 -> S0

interface ArenaSchedulerNet
  :inputs  [cells : Cell Topology  k : Cell Nat]
  :outputs [quiescent : Cell Frozen  contradiction : Cell Contradiction]
```

**Observations.**
1. *On-network?* The executor state (K, partition, capacities, counters, lanes, frozen) is
   modelled as cells on the scheduler's network. Three of them are honestly **non-monotone**:
   `partition` (replace), `exec-idle` and `s0-frozen` (reset at resume). They are declared so and
   confined to `boundary`/`topology` fibers — the stratification *is* where the non-monotonicity
   is put. Off-network: the executor threads themselves and the padded fxvectors — the physical
   realization of the cells, as the CHAMP is the realization of today's network. Not debt.
2. *Impurities revealed.* (a) `exec-idle` as an or-lattice with reset is a counter-shaped thing
   pretending to be a flag: the honest version is a **monotone epoch counter** per executor
   (`idle-since-epoch`), joined by max, compared against the current epoch — no reset. Adopted
   for D.2. (b) The partition as LWW map is fine *only* because it is written at the topology
   stratum; if any S0 code read `partition` and branched, that would be an undeclared stratum.
   Rule: `owner` is read only by the scheduler's dispatch, never by a fire function.
3. *NTT gaps.* No form for `:affinity`/placement (which executor hosts a propagator), nor for
   region lifetime on a cell (`:region :query`). Both are scheduler/storage metadata of exactly
   the kind `specialized-cell-meta` carries — candidates for the NTT design doc's cell metadata.
4. *Inexpressible.* The memory-order annotations (release/acquire). NTT has no memory model; it
   shouldn't — but the DIRECT protocol's correctness cites Racket's, and D.2 must quote the
   reference section (Stage 1 §6).

## 11. Self-critique

## Appendix A — O-3: what the observer is, what DIRECT breaks, and the trade-off

### A.1 What exists (read at `7a0116ec`)

`current-bsp-observer` (`propagator.rkt:572`) is a parameter holding a callback
`(bsp-round → void)`; the BSP inner loop calls it **once per round** (`:3429`) with a
`bsp-round` record (`:554`): `round-number`, **`network-snapshot`** (the immutable CHAMP at
round end), `cell-diffs` (`cell-id old new source-propagator`, `:539`), `propagators-fired`,
`contradiction`, `atms-events`. `current-bsp-round-stats` (`:578`) is a box collecting
`(worklist-size fire-ms merge-ms write-count deferred-count)` per round. Consumers:

| consumer | uses |
|---|---|
| `lsp/server.rkt:547` (`bsp-observe`) | visualization Phase 1 — rounds to the editor |
| `prop-observatory.rkt:204` | captures a `prop-trace` (initial, rounds, final, metadata) per subsystem run |
| `trace-serialize.rkt` | JSON of `bsp-round`/`cell-diff`/`prop-trace` (`2026-03-12_PROPAGATOR_VISUALIZATION_DESIGN.md` §Phase 2) |
| `tools/measure-production-n.rkt` | fires per round (PAR Track 2 R1) |
| `benchmarks/micro/bench-bsp-round-stats.rkt` | the stats box |
| `tests/test-trace-data.rkt`, `test-trace-serialize.rkt` | pins the record shapes |

Not a consumer, by design: `error-explanation.rkt:22,179` — provenance for errors is
on-network and explicitly refuses the observer ("NO scheduler coupling"). Good: the trace is
for *visualization and measurement*, not for correctness.

**The fact that changes the question**: the **sequential** scheduler already emits exactly
**one** `bsp-round` per quiescence call — round 0, diffs computed initial→final, snapshot =
final (`:2599-2640`). So today's observer contract is *already* scheduler-dependent: under BSP
a "round" is a synchronous step; under the sequential scheduler it is the whole run. The
contract was never "one record per barrier"; it is "one record per unit the scheduler chooses".

### A.2 What DIRECT removes

1. **Rounds**: no global synchronous step inside S0; the only global points are stratum
   transitions. `round-number` as a clock disappears.
2. **The per-round snapshot**: `network-snapshot` is the persistent CHAMP, and maintaining it
   during S0 is precisely the ceremony H-S retires (§6.4). A snapshot can be *materialized* at
   a boundary (one pass over the regions), not per round.
3. **A total order of diffs**: owners know every write's `source-propagator`, but writes on
   different executors are concurrent; the honest order is a partial order (per-executor
   sequence + the "triggered-by" edge the owner has when it enqueues a dependent).
4. `fire-ms`/`merge-ms` per round: there is no merge phase; the analogues are per-executor
   fire time, lane-drain time, and detection latency.

### A.3 Options

**A — minimum: one `bsp-round` per S0 run under DIRECT, per-round form only under BSP.** Exactly
what the sequential scheduler does today. Snapshot = materialized value form at the boundary;
diffs initial→final with `source-propagator` = the *last* writer (lost: intermediate writers);
`propagators-fired` = union over executors; stats = per-run (fires, writes, deltas, detection
latency). Zero cost when `#f` (one parameter read per run, fewer than today). Consumers
unchanged; the visualizer loses within-S0 temporal resolution under DIRECT — it keeps it under
BSP, which remains available for tracing.

**B — write-indexed trace, rounds as a view.** The unit of observation becomes the **write
event** `(cell old new source-propagator executor seq epoch triggered-by)`, appended to a
`trace` cell (append-only lattice, `:query` lifetime) **only when observing**. A round is a
*derived grouping*: by `round-number` under BSP, by epoch (stratum run) under DIRECT, by
derivation depth for a Hasse view. `bsp-round` becomes a view function over the event log;
`trace-serialize` gains an event form; the LSP/observatory read events. Cost when observing:
one event (~80–100 B) per write — comparable to today's `cell-diff` (48 B + cons) *plus* the
diff computation it replaces; cost when not observing: one branch per write (to measure;
expected noise). Touches 6 consumers + 2 tests.

**C — end-of-run diff only, retire per-round observation.** Rejected: the visualization design
and the LSP are live consumers; C discards information A keeps for free under BSP.

### A.4 Adversarial read against the principles

| principle | A | B |
|---|---|---|
| Cell/Propagator/Scheduler orthogonality (`DESIGN_PRINCIPLES.org` § 731) | **perpetuates a violation**: the trace's shape depends on which scheduler ran (round vs run) — already true today, now with three schedulers | **repairs it**: events are scheduler-independent facts; "round" is a scheduler-specific *view* |
| Data orientation (§ 590) | rounds are a control artefact recorded as data | writes are the data; grouping is a query |
| On-network (`on-network.md`) | `current-bsp-observer` is a parameter holding a callback — a listed red flag; A keeps it | the trace is a cell with an append lattice; the observer becomes a propagator reading it (or a consumer at the boundary) |
| Decomplection | conflates "when the scheduler synchronized" with "what flowed" | separates them |
| Provenance / "derivations are how a system explains itself" | last-writer only under DIRECT | full derivation partial order (`triggered-by`), the Hasse diagram the project already draws elsewhere |
| Simplicity of foundation | one call site changes | 6 consumers + the visualization design doc revised |
| Unification "only while the foundation stays small" | — | risk: tempting to fold `error-explanation`'s on-network provenance into the same log; **don't** in this track — two purposes, keep separate until a measured reason appears |
| Correct by construction | nothing to break | the event log is append-only and monotone — but *observing* must not change the fixpoint; a property test (observed vs unobserved fixpoint equality) is required |

### A.5 Recommendation (TASTE, with the measurement that would change it)

Do **A in PAR 4 P3** — it is the existing sequential contract, costs nothing, and keeps
per-round tracing under BSP, which stays a supported scheduler. State the contract honestly in
`propagator.rkt:569`: *"one `bsp-round` per scheduler-chosen unit: a BSP round, or a whole S0
run under the sequential and arena schedulers."* File **B as a DEFERRED item** owned by the
visualization series (owner's call which series), with the orthogonality violation named as
the reason it is debt, not polish. Measurement that would move B into PAR 4: if P3's parity
work needs the derivation partial order to *diagnose* a divergence (which it may — "which
executor wrote this first" is exactly what a K>1 parity failure asks), then B's event log is
a P3 debugging tool and should be built then, minimally, rather than later.
