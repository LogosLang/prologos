## 1. What Was Built

Rel Track 1 made the relational language **correct, typed, and writable**, and
absorbed a spin-out that turned out to be a live silent-wrong-answer bug in the
compiler core.

Three things a user can now do that they could not on 2026-07-19, all visible in
one program (this is a real before/after, run at both commits during X.close):

```prologos
defr fruit-color [?fruit ?color]
  || "blueberry" "blue" | "banana" "yellow" | "cherry" "red"   ;; POL.7: `|` rows

defr fruit-not-of-color [?fruit ?not-color]
  &> fruit-color fruit color        ;; POL.8: parens dropped; layout decides
     not (= color not-color)

(fruit-not-of-color f "red")        ;; POL.9: parens make a goal — implicit solve
;; '[{:f "blueberry"} {:f "banana"}] : [List {:f String}]
```

- **Correctness (Aspect A).** Negation-as-failure leaked under open-variable
  enumeration: one `naf` bit served an entire conjunction, so only *{both}* or
  *{neither}* was expressible. `solve (unlicensed lv)` returned all 8 vehicles.
  Fixed by **per-binding belief narrowing** in the S1 stratum handler — each
  enumerated binding is evaluated under its own worldview and the failing
  bindings' fact-bits are cleared. Top-level `not` goals also *echoed
  unevaluated*; they now run. Guards and floundering rounded out the aspect.
- **Typing (Aspects B + B3).** `solve` was a bare `expr-hole` in both checkers.
  It now yields typed per-solution **rows** from three first-class sources:
  schema projection, fact observation (codata, heterogeneous → union), and — the
  owner's headline aspect — **rule-bearing relations**, typed by a static
  body-goal dataflow walker with a Kleene fixpoint that types transitive
  closure. `solve` output composes with the CIU T6 F1 records system: `.field`
  projection, `def`-binding, `validate`.
- **Writability (the POL roster).** Ten polish items from an owner
  hand-testing pass: arity mismatches became hard errors with SWI-style
  diagnostics; `def` binds the WHNF-reduced value (snapshot semantics);
  declaration-order keys; anonymous-variable keys dropped; and the syntax
  cluster above.
- **The SUB spin-out.** `shift`/`subst` treated `expr-champ` (a runtime map) as
  a **closed leaf** on the strength of a comment that said so. A lambda whose
  body was a map literal silently dropped its beta argument; `shift` never
  renumbered, so indices could capture. `?bvar0 : Nat` printed at top level with
  **0 errors** — and the full suite had been green with this live for months.
  Fixed at the root: `nf` now opens binders NbE-style, so containers can only
  capture deterministic `#%nbe` fvars, which `shift`/`subst` are already
  identity on. The invariant became **true by construction** rather than
  asserted. A compiler-wide **−18% suite** win (`PLT_CS_COMPILE_LIMIT`) fell out
  of the same investigation.

## 4. Bugs Found and Fixed

~13 defects plus one recurring class. The headline and the most instructive:

### 4.1 SUB — runtime collections as closed leaves (the headline)

**Symptom**: `?bvar0 : Nat` printed at top level, 0 errors.
**Root**: `shift`/`subst` skipped `expr-champ` because a comment asserted it held
no de Bruijn variables. It could: `nf` constructed containers *under binders*.
Two independent failure modes — `subst` dropped the beta argument; `shift` never
renumbered, so `subst`-under-a-binder produced **variable capture**.
**Why the wrong path seemed right**: the assertion was *nearly* true (containers
usually are closed), the only design note in the file said so, and every
*transforming* layer skipped while the only layer that *descends* is
pretty-print — so the bad term was faithfully printed by the one layer that
could never fix it.
**Fix**: ruling (D) — champ **is** a closed value; make it true by construction
via NbE open-the-binder, rather than policing it with arms.
**Cost, re-measured at X.close**: none (§7).

### 4.2 The rest, briefly

| Bug | Root | Why it looked right |
|---|---|---|
| NAF open-var leak | one naf-bit per conjunction, inherited by every enumerated binding | ground queries route to a *correct* DFS path, so it "worked" in testing |
| Top-level `not` echo | dispatch handled app/rel/unify/is then `[else echo]` | the echo looks like a value |
| 3 on-network guard bugs | struct conditions not recursed; single bit can't filter per-row; S0 narrow re-projected | `gt` goes *stuck* → `truthy? [else #t]` → silent pass |
| `def := solve(…)` "Multiplicity violation" | qtt inferQ'd the goal HEAD (a raw symbol, no arm) and propagated tu-error | the message names a real subsystem, just not this one |
| POL.6 "cannot infer" | WS splits `[x:Int]` into two elements ⇒ silently **2-ary** defn | the arity-lenient engine let a wrong-arity call succeed |
| POL.7 `\|` garbage rows | `$pipe` flowed into `parse-datum` as a term | rows appeared, just with `unknown`s |
| `narrow-subst-bvars` nil | `[_ expr]` catch-all + no map/vec decomposition in `narrow-match` | returns `nil`, which is a legal answer |
| SC preparse gap | `process-string-ws` made cell-pipeline-only, dropping preparse macros | `process-file` worked, so it looked like a config problem |

**The recurring class** (3rd data point, one instance **still live**): an
un-arm'd AST node in `inferQ` surfaces as a spurious *"Multiplicity violation."*
Filed with the structural fix direction: apply the Exhaustive-Walkers answer to
`inferQ` so a missing arm degrades to imprecision, not a false failure.

## 5. Design Decisions and Rationale

| Decision | Rejected | Load-bearing argument |
|---|---|---|
| **A.2: E-with-B** (belief-layer per-binding narrowing) | D (existence narrowing via `solver-retract`) | **Belief ≠ existence.** A NAF contradiction is a per-branch *belief*; belief-narrowing coexists with row enumeration, existence-narrowing clobbers it via projection re-fire. This **inverted** the initial purity judgement — D looked "purer" until the probe. |
| **POL.9: parens make goals** | registry lookup on the head name | **Free-ordering requires syntactic category-decidability.** Under registry lookup a phrase's *category* pends on name resolution — un-typeable, un-composable, retroactively re-categorized. Under parens the category is static and only the *binding* residuates, which is the pattern the driver's demand loop already implements. |
| **SUB: ruling (D)**, champ is closed | (A) add champ arms to all ~37 traversal sites | Correct-by-construction beats policing: NbE makes the invariant true, the tripwire *asserts* it, and no arm can be forgotten. |
| **C.c: schema ⇒ facts-only** | the audit's blocking clause-conformance check | The audit-driven check was **incomplete** (misses transitive `=`, `is`, compound bindings). Rejecting the ill-formed input is *stronger* than guarding the typer — and needs no `has-clauses?` guard (belt-and-suspenders avoided). Owner redesign. |
| **POL.10: WHNF, not nf** | eager `nf`; a value-class taxonomy | **Reduction DEPTH is the axis.** All three "value-class collisions" were nf-under-binder casualties; at WHNF every one dissolves because `expr-lam` is whnf-trivial — binder-headed values stay lazy *by identity*, not by carve-out. |
| **POL.1: bag semantics stays** | dedup | Row multiplicity **is** the derivation count (ATMS-as-provenance, ℕ-semiring); Prolog `findall` parity. |
| **Q_B: local-only namespace gate** | import-inclusive gating | The corpus legitimately shadows refer-imported `xor`/`singleton` with defrs. Local-only fell out of the existing lookup cascade rather than being built. |

## 6. What Went Well · Wrong · Lucky · Surprising

### Went well

- **Failing-test-first found what a green suite could not.** The SUB bug was
  live under 470/0 for months. Only writing the failing repro first exposed it.
- **The tripwire was framed as an assertion, not a second mechanism** — an
  explicit refusal of belt-and-suspenders, with the argument written down. Same
  at C.c (no typer guard). This is the cleanest recurring-lesson *success* in
  the 10-PIR window.
- **Correct-by-construction as a design forcing function.** B3.0's key filter
  had to land atomically in both the runtime and the static half; reading the
  seam caught it mid-phase *because* the CbC invariant made the asymmetry visible.
- **Instrument-the-parse.** Two roots (POL.6, POL.7) were found by a temporary
  `eprintf` on the real `process-file` path after code-reading and end-to-end
  behavior *disagreed*. Neither would have been found by inference.
- **Per-phase discipline held**: 87% of code commits carry tests; zero test-only
  commits; every phase updated tracker + dailies.

### Went wrong (built, then reverted)

- **POL.10 eager-`nf`**: hit three semantic collisions in succession, reverted
  per the diagnostic-protocol stop-rule (≥3 fixes ⇒ reframe). The second pass
  built nf- and whnf-variant driver clones and *ran the collision programs* —
  the taxonomy dissolved. The revert was the cheapest step in the arc.
- **A.4 on-network guard**: fully built and verified, then reverted for the
  simpler DFS route and captured for BSP-LE T3.
- **POL.9b over-reach**: dispatched on any marked def RHS; the suite caught
  sexp-style paren-defs embedded in WS fixtures. The fix (stamp only `:=`
  rewrites) made "the `:=` surface is what makes the RHS command position"
  structural rather than disciplinary.
- **A long A.4 detour** chased a "tabling blocks guards" conclusion that was a
  **probe artifact** — one-line multi-row fact literals mis-parsed. The lesson
  became a Watching entry and, ultimately, POL.7.

### Where we got lucky

1. **The SUB bug never crossed a module boundary.** Four `def`-store routes were
   blocked by *independent* def-seam typing gaps. Had any one worked, poisoned
   terms would have been written into `.pnet` caches and the fix would have
   needed cache invalidation. We were saved by unrelated bugs.
2. **A `git stash` nearly applied an owner stash** during a POL.10 A/B. Caught
   and aborted; now a standing "never stash here" rule.
3. **An unverified probe claim reached the owner** — an audit asserted a
   `def r := [random …]` result; `random` does not exist in Prologos. Caught
   after the fact.
4. **The one perf claim that was wrong got retracted rather than shipped**, and
   only because the author re-tested the mechanism instead of trusting a wall
   delta measured hours apart.

### Surprises

- **Per-token srclocs survive to `parse-defr-body`** — the "WS flattens defr
  bodies" premise, inherited from POL.6/POL.7, was simply false. The reader's
  indent grouping already produced most of POL.8's target structure; the owner's
  nested-`not` form parsed *correctly before any change*.
- **`(dbl 3)` was live, working paren-application in WS** — so POL.9's named
  cost was *realized*, not avoided. The Phase-0 census was supposed to show
  "error ⇒ additive"; it showed otherwise for one head class.
- **`?x:Type` was already half-built** — the `?var:C1:C2` narrowing chain, live
  in sexp and **dead in WS**. All five audit facets missed it; the completeness
  critic caught it.
- **The relational engine's scale ceiling is structural**: one worldview bit per
  fact row (bignum past 62), Tier-2 unreachable by construction for 1-variant
  tables, and **no DFS↔Tier-2 crossover ≤1000 rows** — the `:auto` threshold of
  256 points the wrong way.

## 8. Architecture Assessment

**It held, with one honest asterisk.**

- **Clean integration**: typed rows ride the F1 records/rows machinery "one
  layer up" — the 5th-refusal check in `infer-on-network/err` carries nested
  solve composition into the imperative fallback exactly as records already do.
  No new typing substrate was needed.
- **The propagator substrate absorbed the NAF fix** at its existing S1
  between-round stratum, using per-branch bits the fact/clause installers
  *already* allocated (propagator-design.md Variant C). No new primitive.
- **The reader had more structure than we knew** — POL.8 needed no reader
  changes at all.
- **Friction point (named, not hidden)**: the on-network row *computation* is
  off-network, at exact F1-records parity. The `#f` dispatch is on-network; the
  computation is an imperative return value. Retirement is the joint
  records+solve flip, owned by BSP-LE Track 3. The Network Reality Check was
  applied and the answer written down rather than glossed.
- **Two DFS-routing scaffolds** (`reachable-has-body-local-rule?`,
  `reachable-has-guard?`) are named scaffolding with a named retirement owner
  and a seed document carrying the prototyped-and-verified replacement.

statements existed (STATE head "9+1"; a LOG entry double-booking slot 10; the
handoff publishing 11 while its own parenthetical enumerated 12), and it was
never updated after POL.7 while ≥4 more landed. **The discrepancy was itself the
finding** — it exposed that the refutation/surprise boundary was undefined.

**✅ RESOLVED (owner ruling Q_N3, 2026-07-25)**: `POST_IMPLEMENTATION_REVIEW.org`
q13 now carries a strict three-part definition — a REFUTATION requires a premise
**recorded in a durable artifact beforehand**, shown false **by evidence**, that
**changed the design or implementation**; everything else is a SURPRISE, recorded
but not counted. Plus: **state the count once, at close, with the enumeration**
(the running mid-flight tally is what double-booked slot 10). Under the strict
definition this track's ~29–32 reclassifies mostly to surprises, which
*validates* the published ~11 rather than inflating it — the recount is left to
whoever next cites the cascade.

The most instructive: `install-conjunction` was the *designed* home for the
floundering gate, and **the author's own A.2b change, landed the same session,
broke it** — a design invalidated by an adjacent change in-flight.

### What we learned about the problem

- **Free-ordering requires syntactic category-decidability** — the insight
  behind POL.9, and it generalizes past the relational surface.
- **Belief ≠ existence in a solver** — belief-narrowing coexists with row
  enumeration; existence-narrowing clobbers it.
- **Rule relations derive rows no fact exhibits**, so static observation of rule
  output is an unsound lower bound. The inductive/coinductive split follows.
- **Arity leniency is a diagnostic amplifier** — it turned a wrong reader-shape
  inference into a plausible end-to-end result. Loudness at registration buys
  more than tolerance.
- **The capability system IS the purity gate** — an effectful top-level `def` is
  structurally unconstructible, dissolving a design concern rather than handling it.

### Are we solving the right problem?

**POL + SUB = 1,671 of 3,689 lines = 45% of production churn** — and neither was
in the Stage-3 decomposition at scope-lock. §3 planned four aspects and a
*three-item* polish list; the track delivered four aspects **plus** B3
(owner-elevated), phase SC (owner-added), D.2 implementation (beyond Stage-0/1
scope), a **ten-item** polish roster, and a 13-commit spin-out with its own
design doc.

**The Stage-3 decomposition captured roughly half of what the track turned out
to be.** This is not a criticism of outcomes — POL and SUB produced the
highest-value results. But the PIR should say it rather than presenting the
tracker's 18/24 ✅ as a plan met.

**The question it provokes: should usability tracks be scoped from a
hand-testing pass FIRST, rather than deriving polish from a design?** Every POL
item came from the owner using the language. The design process did not generate
them and, on this evidence, could not have.
