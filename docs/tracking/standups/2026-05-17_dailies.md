### Architectural signals from A-tier — three surprises

#### Surprise 1: dispatch predicate is the dominant variable cost

A1a HIT = 52.8 ns / A1b MISS = 256.8 ns. The `meta-universe-cell-id?` predicate does `(current-X-meta-universe-cell-id)` TWICE per cell-id check (once for the truthy guard, once for equal?). Worst-case = 8 param reads + 4 equal? checks → 256.8 ns.

**Implication**: if Phase 1E dispatches at the top of every `that-read`/`that-write` call with this predicate, the routing decision can DOMINATE the cost. For surface-position reads (the 90%+ case), the predicate misses → 256.8 ns overhead on a 32 ns baseline read. **That's a 8× slowdown for the dominant path.**

**Mitigation candidates** (for design dialogue):
- Coalesce the 4 parameters into 1 (a SET of universe-cids, single param read + memq)
- Use a sentinel encoding (e.g., universe-cids are negative integers, surface-cids positive — cheap branch)
- Cache the "is-universe" flag on prop-net-warm (4th §4.6 cache instance candidate)

#### Surprise 2: A4 cache lower bound at 16.6 ns is BELOW current M1 baseline

If we can engineer the specialized-cell-cache to approach A4's lower bound (~21 ns including ~5 ns cache-access), then **routing to universe cell becomes FASTER than reading from attribute-map**. The optimization inverts the cost asymmetry.

This makes J-C the natural winner — Phase 1E unifies the API surface AND improves performance, not just preserves it.

#### Surprise 3: `resolve-worldview-bitmask` `with-handlers` anti-pattern (likely)

A4 vs M5a breakdown: 207 ns - (30 elab-cell-read + 13 hash-ref) = ~164 ns of which 16.6 is `tagged-cell-read at wv=0`. The remaining ~147 ns is `resolve-worldview-bitmask`. Inspecting [`meta-universe.rkt:288-299`](../../racket/prologos/meta-universe.rkt):

```racket
(define (resolve-worldview-bitmask enet)
  (define per-prop-wv (current-worldview-bitmask))
  (cond
    [(and per-prop-wv (not (zero? per-prop-wv))) per-prop-wv]
    [else
     (with-handlers ([exn:fail? (lambda (_) 0)])
       (define v (elab-cell-read enet worldview-cache-cell-id))
       (if (number? v) v 0))]))
```

**This is the SECOND instance of the workflow.md "defensive `with-handlers` preserved for safety" red-flag pattern**. Same shape as PPN 4C S2.c-iii Move B+ found in `meta-domain-solution`. The guarded condition (worldview-cache-cell missing) is structurally impossible in production (always allocated at make-prop-network). Retiring this `with-handlers` should drop ~100-150 ns per call.

**Pre-Phase-1E candidate optimization**: retire `with-handlers` in `resolve-worldview-bitmask` (Move B+ pattern application). This is a small, structurally-bounded fix that benefits ALL `compound-cell-component-ref` callers, not just Phase 1E.

Combined optimization potential: M5a 207 → (− 100 ns `with-handlers`) → ~107 → (− 30 ns specialized-cell-cache) → ~77 ns. Closing the gap to M1 (32 ns) is now plausible.
