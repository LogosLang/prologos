### Architectural signals from M-tier data

Four findings the data delivered:

1. **Routing-dispatch cost is the J-C bottleneck.** Under J-C, `that-read am meta-pos :type` would route to `compound-cell-component-ref` — that's 207 ns vs 32 ns baseline. §7.6.16.4 wrote ≤ 200 ns as target; we're at 207 ns at the underlying primitive BEFORE adding any dispatch predicate.

2. **The write side is over-budget.** Target ≤ 300 ns; M6 is 445 ns. Cost is structural to `tagged-cell-value` wrapping + `resolve-worldview-bitmask` + per-component CHAMP write. Not pessimization we can peel off.

3. **`meta-solution` full dispatch carries another ~120 ns** over `compound-cell-component-ref`. Implication: Phase 1E should route to the primitive (`compound-cell-component-ref`), not the public shim (`meta-solution`).

4. **M2 vindicates magic-keyword routing as cheap.** `:term` adds ZERO measurable overhead vs `:type` (31.7 vs 31.8) — the dispatch is one `eq?` check in a `cond`. Extending the pattern to `:mult`/`:level`/`:session` is essentially free at the dispatch layer; the cost is in WHERE the dispatch routes.

### The §G semantic gap surfaces as a speculation-semantics gap

The data sharpened the §G observation: universe cells carry **worldview-tagging via `tagged-cell-value`**; attribute-map does NOT. Under §J Option A (J-A: facets on attribute-map):
- (a) lose worldview-tagging for mult/level/session — but Phase 3 (union types via ATMS) NEEDS it;
- (b) add worldview-tagging to attribute-map — touches every facet; much larger scope;
- (c) mirror universe-cell writes to attribute-map — belt-and-suspenders anti-pattern.

This is a stronger argument against J-A than just storage cost. **J-A breaks the speculation semantics Phase 3 depends on.** J-C wins on architectural grounds; the open question becomes "how do we make the J-C access cost tolerable?"
