### Rel T1 POL.6 FIXED — fused `x:Int` in defn params (`0f6dc98c`)  (2026-07-25, code commit)

The owner's last standup repro. `defn my-square [x:Int] : Int` → `Int -> Int`, computes.

- **Root, instrumented not inferred** (the standing Watching-2b lesson earned its keep again): a temporary `eprintf` on the real `process-file` path showed WS delivers the param list as the TWO elements `x` + `:Int` — *the exact shape C.b.2 already handles* — but a `defn`'s params never route through `parse-binder`. `parse-defn-bare-params` mapped `binder-info` over the RAW elements, so the function silently became **2-ary with a parameter named `:Int`**, both hole-typed. ### Rel T1 B3.2 LANDED — display-time coinductive refinement; **B3 COMPLETE** (`df428f7e`)  (2026-07-25, code commit)

The owner's headline aspect is now whole: B3.1 gave rule solves static row types; B3.2 adds the coinductive half at the display seam.

- **What it does**: **SHARPEN** — `solve (mixed 1 v)` on a heterogeneous fact column echoes `{:v String}` instead of `{:v String | Int}` (exact for THIS result set), while a genuinely heterogeneous result keeps the union. **FILL** — a hole field takes the observed type of the values present.
- **The division is visible and test-pinned**: `def r := solve (mixed 1 v)` announces `{:v String | Int}` (the STORED static type, which governs composition) while echoing `r` shows `{:v String}`. Display-only, at the eval arm only — deliberately not on def/defr, whose announced type is the type they store.
- **Surprise (a real regression, caught by the suite not by inspection)**: my first cut matched ANY bare record, so an ordinary **dyn-tailed** record value got its holes re-filled — `{:a 1, :b 2} : {:a _ :b _ | _}` became `{:a Int :b Int | _}`, breaking `test-f1b3-width-acceptance`. Those holes are F1b.3's *deliberate* degrade (a dyn tail means the field set is unknown), so refilling them re-asserts knowledge the type system just discarded. Fix = the **CLOSED-tail gate**, which is also the principled scope: D-B3.6 says solve rows are always closed. Named cost: explain rows are 'dyn-tailed, so they aren't refined.
- **Honest scope finding**: **FILL has no reachable surface case today.** B3.1's walker is thorough enough that a hole field almost always means "nothing binds this var" — whose runtime value is an unbound echo, so the hole correctly stays. The one shape that would reach it is blocked by an adjacent defect (below). The FILL path is unit-pinned so it's correct the day that lands — rather than shipping an untested branch or pretending the case exists.
- **Adjacent PRE-EXISTING defect surfaced + deferred, not chased**: unifying a relational var with a **collection literal** yields the runtime value `unknown` while the static type derives correctly — `'[{:m unknown, :x 1}] : [List {:m {:a Int} :x Int}]`.
